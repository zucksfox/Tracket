# Audit UX/UI ServiceTrack & Warranty Hub

Tanggal audit: 24 September 2026
Persona: Kasir pemula, Teknisi pemula mobile/tablet, Pelanggan awam
Acuan: `design.md`, source Blade/JS/controller, route list, live HTTP smoke test

Catatan metode: browser automation tidak dapat digunakan karena Camofox tidak terhubung. Temuan fungsional diverifikasi lewat source trace, Laravel feature tests, live HTTP request, dan build. Temuan ukuran piksel/visual langsung pada 375/768/1280 belum dapat dikonfirmasi lewat screenshot.

## Audit Alur

| Alur | Temuan Masalah | Tingkat Risiko | Saran Perbaikan Konkret |

Badge pelanggan ditemukan membantu, tetapi bila koneksi lambat kasir bisa menekan Simpan sebelum lookup selesai; hidden `customer_id` belum terisi dan sistem dapat membuat pelanggan baru dengan nomor sama/menolak unique, tergantung timing. | Tinggi | Tambahkan status lookup eksplisit: `Mencari...`, `Pelanggan ditemukan`, `Pelanggan tidak ditemukan`, `Gagal mencari`. Copy sudah memperingatkan status tidak dapat diubah kembali. | Tinggi | Jangan memilih default diam-diam; gunakan pilihan radio dengan label `Tanpa garansi`, `30`, `60`, `90`, dan state aktif yang jelas. Tampilkan tanggal berakhir sebelum submit: `Berlaku sampai ...`. Di konfirmasi tampilkan durasi dan tanggal. Validasi role/izin checkout secara eksplisit bila kasir adalah role terpisah. |

Placeholder jelas dan halaman publik HTTP 200. Untuk koneksi lambat belum ada indikator submit/loading yang terlihat dari source. | Sedang | Tambahkan tombol busy state `Mencari...`, cegah double submit, dan pertahankan input saat error. Beri instruksi nomor servis dalam format monospace yang lebih mudah disalin dari nota. |
| G. Pelanggan typo satu digit | Submit typo menghasilkan pesan spesifik yang menyebut data tidak ditemukan dan meminta memeriksa nomor. Namun pelanggan harus mengetik ulang; tidak ada deteksi typo/saran kandidat atau bantuan membaca nomor. | Sedang | Untuk kode berformat `SRV-YYYYMM-XXXX`, tawarkan kandidat hanya bila prefix/tahun sama dan jarak typo satu karakter; jangan tampilkan data pelanggan sebelum verifikasi. Tambahkan tombol `Coba lagi` dengan input tetap fokus. |
| H. Admin membatalkan servis setelah memakai part | Detail > Batalkan servis & kembalikan stok > confirm browser > redirect detail. Yang kurang: stok sebelum/sesudah tidak terlihat dalam layar hasil, dan tombol cancel tersedia pada semua user authenticated, bukan hanya Admin, karena route hanya `auth`. | Tinggi | Batasi cancel sesuai kebijakan bisnis, minimal Admin/Kasir yang berwenang. ## Lima Masalah Paling Kritis Sebelum Demo

1. **Otorisasi pembatalan servis belum dibatasi.** Route cancel hanya `auth`, sehingga teknisi yang dapat membuka detail berpotensi membatalkan servis dan mengembalikan stok. Dampaknya langsung ke status transaksi dan inventaris. Tambahkan authorization test dan policy.
2. **Checkout garansi memakai default 30 hari tanpa state pilihan yang jelas.** Kasir dapat mengaktifkan garansi yang salah; konsekuensinya memengaruhi kartu garansi dan kewajiban bengkel. Gunakan radio/preset dengan state aktif, tanggal akhir, dan konfirmasi detail.
3. **Responsif belum selesai untuk semua modul.** Customers, technicians, reports, dan detail sparepart masih mengandalkan tabel horizontal pada layar kecil. Teknisi adalah persona mobile; ini dapat membuat salah baca qty/status dan salah tekan aksi.
4. **Notifikasi stok belum memenuhi role dan event semantics.** Tidak ada role Kasir, initial snapshot dapat memunculkan toast massal, dan state global localStorage dapat tercampur antar akun. Ini berisiko membuat stok kritis terlewat atau notifikasi kehilangan kepercayaan.
5. **Konflik design.md dengan sidebar aktual serta logo collapsed yang tidak ada.** Design meminta rail + panel collapse, implementasi single sidebar dan test mengunci tanpa collapse. Ini akan terlihat saat demo asesor dan membuat dokumentasi/desain tidak dapat dijadikan acuan yang konsisten.

## Hal yang Sudah Terbukti Berfungsi

- Format nomor HP check-in sekarang strict angka awalan `08`, tanpa memaksa prefix operator tertentu; test valid/invalid lulus.
- Backend add-part menggunakan transaction dan lock stok; qty melebihi stok ditolak.
- Part stok 0 ditampilkan disabled dengan instruksi minta admin menambah stok.
- Cancel melakukan rollback seluruh part dalam transaction dan menampilkan ringkasan part yang dikembalikan.
- Tracking valid/invalid merespons dengan HTTP 200/404 dan pesan error yang spesifik.
- Logout menghapus autentikasi, invalidate session, dan regenerate CSRF token. Verifikasi browser Back masih perlu E2E browser nyata.
- Full suite: 104 tests passed, 343 assertions. Vite build berhasil. `node --check resources/js/app.js` berhasil.
